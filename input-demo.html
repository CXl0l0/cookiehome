THE INPUT LAYER

Understand the signals before interpreting the person.

Cookie Homes combines Chrome cookie metadata, Cookiebot’s recorded category choices, and the site’s published Cookiebot declaration when available. An adapter links and normalizes them into scenarios; neither source replaces asking the user what they want.

✳
Inputs matter just as much as the output.
Good preference extraction starts with good context. Unknown evidence stays unknown; it never silently becomes consent.
INPUT 01◉

Observed cookie metadata

What cookies are visible in the browser? Chrome cookies.getAll() provides name, domain, path, expiry, and security flags.

Chrome extension APIchrome.cookies.getAll({ url })

↳ Describes a cookie’s handling—not its purpose or whether the user agreed to it.

INPUT 02☷

CMP consent signal

What optional categories did the user allow? Cookiebot’s browser SDK exposes boolean choices for preferences, statistics, and marketing.

Cookiebot JavaScript SDKCookiebot.consent.marketing === false

↳ Describes category consent, not an individual cookie decision.

LINKING INPUT⛓

Site purpose catalog

What does the site’s public declaration say? When published, its cookie table lists providers, categories, purposes, and expiry information.

Public Cookiebot declarationcookies[] · Category · PurposeDescription

↳ The declaration may be missing or stale. Unmatched cookies stay unknown.

PROTOTYPE INPUT CONTRACT

Raw records in, guests out

Paste source-shaped examples. The adapter maps Cookiebot categories to Cookiehome categories and links declared cookie names to Chrome observations. References: Cookiebot SDK · Cookiebot declaration · Chrome Cookies API.

Live collection uses the unpacked extension in extension/. It checks the current page and same-site cookie/privacy pages for a published declaration. No Cookiebot API key is needed; if no declaration is found, browser metadata and the SDK can still be collected.

GRACEFUL WHEN THE WEB CHANGES
New cookie? New declaration entry? Keep the pipeline; extend the data.
Store new observations and declaration versions without rejecting the record. A Chrome cookie matched to a public declaration entry can be assigned a category and explanation. Unmatched cookies remain unknown. This prototype supports pasted fixtures and authorized local collection through the unpacked extension; a broader deployment would need secure user accounts, permission controls, durable declaration management, and review tools for ambiguous matches.
